# 完成前验证

用可检查的证据支持完成声明，验证范围与任务风险、影响范围和验收要求相匹配。

## 选择验证方式

- 文档、注释、格式或机械修改：检查实际差异、结构和受影响内容；不自动新增测试或运行全套测试。
- 行为变更或缺陷修复：验证目标行为、原始问题和受影响的回归路径；优先使用仓库已有的有效测试。
- 共享逻辑、跨模块或高风险修改：扩大到相关集成、构建或端到端验证，并完成仓库要求的检查。
- SQL 与数据任务：按实际需要选择静态、样例、全量或消费端验证，检查来源、粒度、分区、关联和输出契约。
- 报表、界面、文档或外部写入：任务要求最终使用效果时，回读或检查消费端可见结果；中间文件生成不能替代验收。

选择足以支持当前声明的最小验证范围。除非任务或仓库要求，不自动将局部修改扩展为全量测试。

## 证据要求

1. 明确要证明的结果，选择能够直接检查它的命令、查询、回读或人工检查。
2. 检查实际结果，包括退出码、失败项、警告和产物；不只看命令已启动或工具返回成功。
3. 确认证据对应最终版本、当前配置和相关环境。本次任务已有有效证据时可以复用；证据产生后的相关修改、环境变化或未解决问题需要针对性重验。
4. 将证据与用户验收要求逐项对应，只声明已经证明的部分。

构建通过、测试通过、缺陷修复和用户验收是不同结论，不互相替代。子代理报告完成后，检查相关产物与证据，再给出结论。

## 失败与限制

- 验证失败时，修复本次改动造成的问题并重跑受影响检查；既有无关失败如实报告。
- 环境、权限或外部依赖使验证无法运行时，说明未验证部分并完成可用的替代检查。
- 不用静态通过宣称运行成功，不用样例通过宣称全量完成，也不用源码或中间产物宣称消费端已验收。
- 追加验证涉及尚未授权的付费、生产写入或范围扩大时，先完成可执行的检查，再确认相关操作；已有明确授权时不重复询问。

## 停止条件

所需检查通过、验收要求得到对应证据支持且没有具体未解决风险时，结束验证并交付。只有新增修改、失败、环境变化或具体未解决风险，才扩大或重复检查。

最终回复先说明结果，再简要给出验证证据和重要限制。未运行、部分完成或受阻时，准确报告实际状态。
