# 执行前澄清

解决会实质影响结果的歧义，但不要让明确任务陷入反复确认。

## 判断规则

1. 提问前先检查仓库、当前文件、配置和已有上下文。
2. 任务明确时，简要说明理解后直接执行，不等待额外确认。
3. 未知项可能实质改变结果时，说明当前理解，区分已确认事实与推断，只询问一到两个阻塞问题。
4. 涉及破坏性操作、外部写入、付费操作、使用凭据或向工作区外发送项目数据时，检查用户是否已授权当前目标、操作和范围。授权明确时直接执行范围内工作，不重复询问；授权缺失或含糊时，在相关操作前确认。
5. 已有授权在当前任务中持续有效。只有目标、操作、成本或数据发送范围发生实质变化，或用户明确要求阶段审批时，才需要新的确认。授权不替代实际身份、权限检查或环境所需的访问许可。

把“95% 把握”视为减少返工的实用阈值，而不是在关键决策已经明确后继续提问的理由。

## 需要锁定的内容

- 目标和可检查的交付物
- 目标文件或数据源
- 指标、日期、产品和人群范围
- 明确禁止修改的边界
- 是否允许执行、全量跑数、联网或外部写入
- 能够证明任务完成的验证证据

不要询问能够安全查明的信息。小任务不强制使用正式模板。阻塞问题解决后，直接执行并验证。
